# Coinplay Road

Три детерминированные игры на canvas, из которых получаются и ролики, и живая страница.
Всё определяется числом `seed`, поэтому любой ролик воспроизводим, а контента можно делать сколько угодно.

- **chart.html** — основная серия: бесконечный график (24/7) с мини-Чадом у билборда: он всегда «купил на уровне», поэтому при итоге ВНИЗ плачет с вывернутыми карманами («Я купил на пике»), при ВВЕРХ показывает палец вверх. Каждые 14 секунд новый раунд: на цене стоит уровень, вопрос
  «выше или ниже через 10 секунд?», потом результат, и сразу следующий раунд. График не останавливается.
- **rekt.html** — «Чад»: серия, где богатенький герой на суперкаре каждый раз красиво разбивается
  (эпизод 12 секунд, примерно в каждом 17-м Чад выживает). Рядом график портфеля, который падает вместе с машиной,
  счётчик «Чад №», чистая стоимость, бегущая строка и подписи-шутки (en, ru, es). Бесконечная серия.
- **index.html** — «Куда поедет машинка?»: конечная механика (развилка A/B/C), для серий «вопрос / ответ».

Билборд: `coinplay.com` и вторая строка `unlock the daily bonus` (меняется параметром `--bonus`). Никаких подписей «not financial advice» в игре нет, дисклеймер планируется отдельно.
`rekt.html` («Чад на суперкаре») оставлен в репозитории, но основной серией считается график с Чадом.

## Запуск

```bash
npm install
npx playwright install chromium   # один раз, если браузера ещё нет
node record.mjs --game chart --seeds 1-10 --langs es,en --audio
```

Нужны Node 18+ и ffmpeg в PATH. Ролики 1080x1920, 30 fps, H.264, лежат в `out/`,
рядом `manifest.json` с ответом для каждого ролика.

## Параметры record.mjs

| Параметр | Что делает |
|---|---|
| `--game chart` / `rekt` / `road` | какая игра (по умолчанию chart) |
| `--episodes N` (rekt) | сколько эпизодов подряд в ролике, ролик = N*12+1 секунд |
| `--episode E` (rekt) | конкретный эпизод; без него берётся первый, где Чад разбивается |
| `--survive` (rekt) | взять первый эпизод, где Чад выжил |
| `--seeds 1-10` или `5,9,12` | какие seed рендерить |
| `--langs ru,en,es,pt,de,tr,lv,lt,hr,sr` | языки текста (график и сцена одинаковые) |
| `--skin gold/cyan/violet/mono` | цветовая схема, по умолчанию по seed |
| `--bonus "текст"` | вторая строка на билборде (по умолчанию `unlock the daily bonus`) |
| `--url coinplay.com/метка` | текст на билборде целиком (разрешено только `coinplay.com` или `coinplay.com/метка`) |
| `--platforms tt,th,ig,yt,x` | отдельный рендер под каждую платформу, на билборде `coinplay.com/<платформа>` |
| `--account es1` | метка аккаунта: `coinplay.com/tt-es1`, попадает в имя файла и manifest |
| `--domain` | домен для меток (по умолчанию coinplay.com) |
| `--audio` | простые звуки: тики последних 3 секунд и сигнал результата (вверх и вниз звучат по-разному) |
| `--rounds N` (chart) | сколько раундов подряд в одном ролике, ролик = N*14+1 секунд |
| `--round R` (chart) | конкретный раунд; без него берётся первый раунд с понятным результатом |
| `--minmargin 6` (chart) | минимальный разрыв между линией и ценой в конце раунда, чтобы результат был очевиден |
| `--pair COIN/USDT` (chart) | подпись пары на графике |
| `--mode full/question` (road) | с ответом или без |

Ролик на 15 секунд заканчивается стартом следующего раунда: новый вопрос и новая линия уже в кадре,
это работает как зацикливание. Ролики `--rounds 3` показывают, что игра не заканчивается.

## Живая версия

**Общий эфир 24/7.** `chart.html` и `rekt.html` без параметра `seed` идут по общим часам: у всех зрителей в любую секунду
один и тот же график, раунд и номер Чада, как стрим. Сервер для этого не нужен, достаточно статического хостинга:
время считается от фиксированной даты, а при открытии с http(s) подстраивается под часы сервера. Эфир всегда идёт на seed 1,
поэтому ролики с `--seeds 1` совпадают с ним по раундам и эпизодам. С `?seed=N` страница идёт приватно, с нуля.
Для круглосуточного стрима страницу можно захватывать как источник в OBS. `index.html` (машинка) в общий эфир не входит.

Открой `chart.html` (или `index.html`) в браузере. Кнопки под полем, счёт хранится в браузере.
Параметры в адресе (`seed` отключает общий эфир): `?lang=es&skin=gold&seed=5&src=tt_es1&bot=https://t.me/ваш_бот`. Текст `bonus` в живой версии из ссылки не принимается (его задаёт только запись роликов), чтобы чужая ссылка не подменила надпись на билборде.
Для Lovable или любого хостинга достаточно положить файл как есть. Для круглосуточного стрима
страницу можно захватывать как источник в OBS.

## Трекинг: как закрыть дыру между роликом и сайтом

В ролике остаётся один билборд, но у каждой платформы и аккаунта он свой: `coinplay.com/tt-es1`.
Пользователь заходит на этот адрес, и вы определяете источник.

1. **Метки на билборде.** `node record.mjs --game rekt --seeds 1-10 --langs es --platforms tt,th,ig,yt,x --account es1`
   Один и тот же seed рендерится отдельно под каждую платформу.
2. **Редиректы** `coinplay.com/tt-es1` на UTM-ссылку настраиваются на вашей стороне (сервер или трекер).
   Готовые целевые ссылки выдаёт `links.mjs`.
3. **Живые страницы** (`play.html` как хаб для ссылки в профиле, `rekt.html`, `chart.html`, `index.html`):
   параметр `?src=tt_es1` превращается в
   - кнопку «Бонус дня» на `coinplay.com/?utm_source=tt&utm_content=es1&utm_medium=game&utm_campaign=rekt` (источник до первого `_`, остальное в content, как в редиректах из `links.mjs`);
   - кнопку бота `t.me/бот?start=tt_es1_rekt` (бот задаётся `?bot=https://t.me/бот` или константой `DEFAULT_BOT`).
4. **События**: `cp_view`, `cp_pick`, `cp_result`, `cp_cta_bot`, `cp_cta_site` пишутся в `window.dataLayer`
   (подходит для GTM). Чтобы слать их в трекер, укажите адрес в константе `HOOK` в странице.
5. **CSV ссылок**: `node links.mjs --base https://ваш-хостинг --bot https://t.me/бот --platforms tt,th,ig,yt,x --accounts es1,en1 --series rekt,chart --withaccount --out links.csv`

Что ещё защищено:
- строка «18+ / играйте ответственно» на всех живых страницах и в хабе (в роликах её нет, это решение по площадкам за вами);
- GTM подключается константой `GTM_ID` в странице (пусто = не грузится), без него события лежат только в `window.dataLayer`;
- у страниц есть Content-Security-Policy: внешние скрипты только с googletagmanager.com;
- `record.mjs` проверяет ffmpeg, seeds, длину метки и сам домен билборда, а `manifest.json` дополняется, а не затирается;
- `npm test` прогоняет проверки ссылок, UTM, списка разрешённых доменов и битого localStorage.

Безопасность: параметры `bot` и `site` принимают только https на `t.me` / `telegram.me` и `coinplay.com`,
иначе подставляется безопасное значение. Метка `src` очищается до букв, цифр, `_` и `-`.
Адрес сборщика событий намеренно не берётся из ссылки.
Спросите на регистрации «как вы о нас узнали»: это поймает просмотры без клика.

## Чат (как у Bustabit): сервер и модерация

`server.mjs` раздаёт игры и держит анонимный чат под графиком (на телефоне график сверху и чат под ним, на широком экране рядом).
Запуск: `npm install && npm start`, открыть `http://localhost:8080`. На Railway достаточно подключить репозиторий:
команда запуска `npm start`, переменные ниже. Со статического хостинга или из файла чата просто нет, игра работает как раньше.

| Переменная | Что делает |
|---|---|
| `PORT` | порт (Railway задаёт сам) |
| `TRUST_PROXY=1` | включить на Railway: IP берётся из заголовка прокси |
| `ADMIN_TOKEN` | секрет для модерации; пусто = админ-команды выключены |
| `ALLOWED_ORIGINS` | необязательно, через запятую (по умолчанию чат принимает только свой хост) |
| `DATA_FILE` | где хранить очки (по умолчанию `./data/scores.json`) |
| `MAX_CONN_PER_IP` | лимит соединений с одного адреса (10) |
| `FRAME_ANCESTORS` | кто может встраивать страницы в iframe (по умолчанию только свой сайт) |

Как устроен чат:
- Анонимно: ник вроде `LuckyFox42` выдаёт сервер по случайному токену в браузере. Комнаты отдельные для каждой игры и языка.
- Фильтры: ссылки, домены, телефоны, адреса кошельков, @упоминания, популярные скам-фразы (en/ru/es), обход вида `coinplay (dot) com`.
  Список лежит в начале `server.mjs`, его нужно дополнять по реальным спам-волнам и под свои языки.
- Лимиты: 1 сообщение в 1,5 с и не больше 5 за 20 с, повторы отклоняются. Три срабатывания фильтра за 10 минут дают мут на 10 минут, повтор в 3 раза дольше.
- Жалобы: 3 жалобы от разных пользователей скрывают сообщение у всех.
- Модерация вручную:
  `curl -X POST $URL/admin/mute -H "Authorization: Bearer $ADMIN_TOKEN" -d '{"nick":"LuckyFox42","minutes":60}'` и
  `curl -X POST $URL/admin/delete -H "Authorization: Bearer $ADMIN_TOKEN" -d '{"id":123}'`.
- Данные: история (50 последних) и муты хранятся в памяти, после перезапуска сбрасываются. IP хранится только в виде соленого хэша, в журнал ничего не пишется.
- Проверка: `npm run test:chat` (два браузера, фильтры, лимиты, жалобы, админ, чужой Origin).

### Прогнозы, очки и таблица лидеров

Прогноз можно сделать кнопкой или словом в чате (`UP`, `ВНИЗ`, `SUBE`, `REKT`...: одно слово, без других слов, регистр и знаки не важны).
Раунд определяет только сервер по общим часам, клиент его не передаёт. Приём закрывается за 0,5 с до итога (chart) или за 0,3 с до удара (rekt),
плюс 0,35 с запаса на сеть. В раунде один прогноз на пользователя. Итог приходит всем, кто сделал прогноз, и считается по тому же `engine.js`, что рисуют страницы.

- chart: верный прогноз = 1 очко.
- rekt: по коэффициенту, чтобы «всегда REKT» не был лёгким выигрышем: «разбился» = 1 очко, «выжил» = 16 очков.
- Таблица «Топ дня» (по UTC, кнопка 🏆 в шапке чата) показывает 10 лучших, у игрока свой счёт, серия и место.
- Очки хранятся в `DATA_FILE` (по умолчанию `./data/scores.json`) в виде хэшей токенов, записи старше 30 дней удаляются. На Railway подключите том
  и укажите, например, `DATA_FILE=/data/scores.json`, иначе очки пропадут при каждом деплое.
- Очки считаются только в общем эфире. С `?seed=N` игра приватная и по-прежнему считает локально, `road` очков не имеет.
- Часы страницы сверяются с сервером через чат с точностью до миллисекунд; без чата используется заголовок Date (точность около секунды).

**Честно про защиту от накрутки.** Страница содержит те же формулы, что и сервер (иначе нельзя рисовать график и ролик), поэтому скрипт может
заранее вычислить ответ. Сейчас стоит только статистический фильтр: игрок с невозможно высокой точностью (chart: больше 80% после 50 прогнозов,
rekt: больше 1,6 очка за прогноз после 60) пропадает из таблицы. Этого достаточно для игры без призов. Если появятся призы, нужно перевести эфир
на секретный seed на сервере и отдавать клиентам цену потоком, не раскрывая будущее. Для rekt придётся ещё и сдвигать показ исхода, потому что
анимация эпизода показывает его с самого начала.

Вёрстка: `npm run test:layout` проверяет 15 размеров экранов (от 280 до 2560 пикселей, портрет и ландшафт, с чатом и без): нет горизонтальной прокрутки, игра и кнопки помещаются, поле ввода достижимо. На телефоне в портрете игра сверху и чат снизу, в ландшафте игра слева, кнопки и чат справа, на широком экране игра и чат рядом. Пустые поля кадра сверху и снизу в живой версии обрезаются, на ролики это не влияет.

Тесты: `npm run test:all` (около 6 минут) запускает проверки ссылок, ядра, вёрстки, чата и очков по очереди.

## О серии про Чада (rekt)

Юмор мультяшный: никакой крови, никаких реалистичных травм, провал показан купюрами, обломками,
призраком в очках и штампом REKT. Машина безымянная, без настоящих логотипов. Тексты шуток лежат в объекте `CAP`
в `rekt.html`: для en, ru и es они есть, для остальных языков подставляется английский. Новые эпизоды
(ракета, яхта, башня из денег) добавляются как новые сцены на том же скелете: завязка, нарастание, провал, штамп, сброс.

## О графике

Цена синтетическая (шум по seed), это не котировки реальной монеты. Подпись `COIN/USDT` стоит
для того, чтобы не выдавать выдуманную цену за реальную. Для реальной цены понадобится подключить
поток биржи и пустить его в функцию `price()` в `chart.html`.

## Что менять под себя

- Тексты и языки: объект `TXT` в начале скрипта. Переводы на lv, lt, hr, sr и tr стоит проверить носителем.
- Бренд: единственный билборд `billboard()`, других упоминаний сайта в кадре нет.
- Тайминги раунда: константы `P`, `PRED`, `SHOWEND` в `chart.html`.
- Характер графика: массив `OCT` (периоды и амплитуды шума) и множитель в `price()`.

## Серия «Чад с 3 жизнями» (формат под TikTok-удержание)

Один герой, несколько раундов подряд, растущие ставки: зритель переживает за Чада.

```
node record.mjs --game chart --series --seeds 3,7,12 --langs ru,en,es --audio --platforms tt,th,ig,yt,x
node record.mjs --game chart --series --arc rekt --seeds 3 --langs en --audio     # другой финал
```

- `--series` — 4 раунда подряд (≈57 с), у Чада 3 сердечка; каждый раунд «ВНИЗ» стоит жизнь. `--rounds 3..6` меняет длину.
- `--arc survive|rekt` — финал. Движок сам ищет отрезок графика, где перед последним раундом у Чада ровно 1 жизнь и всё решает последний раунд (исходы раундов не меняются, это те же детерминированные раунды).
- Сверху подпись-крючок на весь ролик («ты не можешь сдаться, когда даже Чад не сдался:» для survive, «У Чада 3 жизни. Дотянет до конца?» для rekt), на 10 языках. Переводы lv/lt/hr/sr/tr/pt/de нужно показать носителям.
- С `--audio` идёт непрерывный фон (пульсирующий бас, нарастающий тон перед каждым решением) плюс сигналы и финальная мелодия.
- Файлы: `chad_s<seed>_<lang>_<arc>_r<N>[_<платформа>].mp4`.
- Подпись лежит в верхних ~100 px. Для TikTok это зона интерфейса: перед массовым запуском проверьте на телефоне.

## Язык

Пока всё на английском: ролики по умолчанию `en`, живой сайт, хаб и чат тоже открываются на `en` независимо от языка браузера (одна комната чата на игру). Остальные языки остаются в коде и включаются явно: `?lang=ru` на сайте, `--langs ru,es` в рекордере.

## Монета на трассе (coin.html)

Тот же раунд, что в chart (движок общий, исходы те же), но график показан как рельеф: монета катится по свечам, камера едет следом и наезжает к решению, ворота стоят на уровне линии, на итоге вспышка, искры и тряска. Адрес стоит придорожным знаком внизу. Только запись роликов.

```
node record.mjs --game coin --seeds 5,7,9 --langs en --audio --platforms tt,th,ig,yt,x
```

## Развилка с видом сзади (drive.html)

Псевдо-3D: камера за машиной, дорога уходит вдаль, впереди развилка со знаками A/B/C. Машина виляет, потом сворачивает на одну из веток; ответ зависит только от seed. Адрес стоит на придорожных щитах. Только запись роликов, 15 с.

```
node record.mjs --game drive --seeds 5,7,9 --langs en --audio --platforms tt,th,ig,yt,x
```

## Гонка шариков (race.html)

8 шариков с глазами падают сквозь трассу (колышки, воронки, бамперы, ползунки), зритель ставит на имя. Физика детерминирована (без sin/cos), поэтому гонка одинакова у всех при одном seed; победителя определяет физика, а не заранее заданный ответ. Рендерер перебирает варианты гонки и берёт «острую»: несколько смен лидера, плотный финиш, финиш на 10,5–14,5 с (ролик ≈ 17–20 с).

```
node record.mjs --game race --seeds 2,3,5 --langs en --audio --platforms tt,th,ig,yt,x
node record.mjs --game race --seeds 2 --bpm 128 --names moon,pepe,wagmi,hodl     # имена участников (например, слова из чата) и темп
```

- Звук без чужой музыки: счёт по долям такта, удары шариков на сетке восьмых (у каждого шарика своя нота), фанфара на ближайшую долю. `--bpm` подстраивает ритм под трек, который вы добавите при публикации.
- Адрес бренда напечатан на «полу» трассы крупно и еле заметно, плюс `--url`/`--platforms` как раньше.
- Подтягивание отстающих (лёгкий «резиновый» эффект) держит стаю вместе, чтобы были обгоны.
- В живой эфир (общий для всех зрителей, с чатом внизу) эта сцена переносится следующим шагом: имена возьмутся из слов в чате.
- **Мат в репликах.** При обгоне проигравший шарик ругается в пузыре («fuck», «oh fuck», «wtf»…), выигравший иногда подкалывает («ez», «get rekt»). `--swear bleep` (по умолчанию) показывает «f*ck» и ставит писк цензуры на звук, `--swear full` пишет как есть, `--swear off` убирает реплики. Список реплик лежит в `race.html` (LOSE/WINS) и пишется в manifest (поле speech: время, имя, текст), чтобы позже подложить настоящую озвучку.

### Драма, характеры и музыка гонки

- **Порталы.** Зелёный «+» перебрасывает шарик вперёд, красный «?» отбрасывает назад; у самого финиша стоит большой красный портал, который может швырнуть лидера назад. Зелёные площадки «»»» дают рывок. Рендерер выбирает гонки минимум с двумя портальными событиями и несколькими сменами лидера.
- **Характеры** (слова из чата получают характер по хэшу имени): chad (очки, самодовольный), degen (повязка, в хвосте кричит ALL IN и получает рывок), hodl (алмаз), pepe (слёзы), whale (фонтан), wagmi (улыбка), rekt (крестики вместо глаз), bear (уши). Фразы персонажей лежат в `PERS` в `race.html`.
- **Музыка** (`music.mjs`): фонк-бит 140 уд/мин (кик, 808, хэты, колокольчик, паттерн зависит от seed), отсчёт и «дроп» на старте, звуки событий (удар, обгон, портал, рывок, ALL IN, писк цензуры) и финальный аккорд. Вся музыка синтезируется в коде, без чужих треков; `--bpm` меняет темп, без `--audio` звука нет.

### Разные трассы и бренд в гонке

- **Каждая гонка с другой трассой.** Набор препятствий, их частота и густота зависят от seed гонки: колышки, воронки, бамперы, ползунки, диагональные планки, порталы, площадки-ускорители, ленты-конвейеры (толкают вбок) и грязь (замедляет). Для эфира 24/7 каждый новый раунд берёт новый seed, поэтому трассы не повторяются.
- **Название сайта.** Крупные баннеры «coinplay.com» подвешены над трассой (три на гонку), на полу и на финише тоже домен. На экране всегда только домен; метка платформы (`/tt`) не показывается, она остаётся в имени файла и manifest. Вернуть её на экран можно флагом `--showtag`.


## Живая гонка 24/7 (race.html)

Одна гонка на всех зрителей: сервер ведёт цикл 40 с по общим часам (как chart/rekt).

- 0–7 с: ставки. Имена 8 участников известны, seed гонки скрыт, победителя заранее не вычислить.
- 7 с: ставки закрыты, сервер рассылает `rlock {simSeed}`; у всех идёт отсчёт 3-2-1.
- 10 с: старт. Гонка 21–28 с, затем итог и таблица очков до конца цикла.
- Участники следующей гонки: одиночные слова из чата (`[a-z0-9_]{2,10}`, по числу разных авторов), чемпион остаётся, остальное добирается из списка по умолчанию. Мат и оскорбления отсекает `NAME_BLOCK` в server.mjs.
- Ставка: кнопка с именем или слово-имя в чат. Верная ставка даёт 7 очков; очки и топ идут через общую таблицу (`board.race`).
- Клиент и сервер считают физику одним `racecore.js`, итог сверяется тестом `node test-race.mjs`.
- Без сервера страница сама считает гонку из имён по умолчанию, очки не ведутся.
- Запись роликов не изменилась: `node record.mjs --game race ...` (в режиме `?mode=record`).
- Звука в живой версии нет; он только в роликах.

### Геймплей гонки (v2)

- Шарики крупнее (R=13), трасса уже (WW=200) и короче (3000), всё медленнее (G=170, потолок скорости 190). Отстающие ускоряются, лидер притормаживает, поэтому группа держится кучей и толкается.
- На трассе лежат 3 ножа. Подобравший держит нож 6 секунд (на трассе 3 ножа), сам гонится за ближайшим шариком и при касании выбивает его из гонки (шарик отлетает, ставка на него проиграна). Остаётся минимум 3 финиширующих.
- Гонки подбираются перебором (`plan`): окно 21–28 с, смены лидера, порталы, хотя бы одно убийство.
- Сайт: баннеры и надпись на финише убраны. В ролике остаётся одна бледная подпись внизу, на сайте маленькая ссылка под кнопками.
- Любое изменение физики меняет результат гонки, поэтому сервер и клиент должны браться из одного `racecore.js`.

### Клипы 12 секунд и драма на финише

- `node record.mjs --game race --seeds 1-10 --langs en --audio --short` даёт ролики по 11–13 секунд (`race_s<seed>_en_c12.mp4`): короткая трасса, финиш вплотную (разрыв до 0,45 с), хотя бы одно убийство.
- На финише включается замедление и наезд камеры на лидера; при разрыве меньше 0,45 с появляется «PHOTO FINISH». Это только в записи (время кадра переводится в время гонки функцией `rtOf`), на сервере и в живой версии физика не меняется.
- Адрес `coinplay.com` теперь одна крупная печать на сукне, мимо которой проезжают шарики; на всём ролике текст не висит.

### Живая страница на телефоне

В портретном режиме экран делится примерно 50/50: сверху гонка (крупные шарики, заголовок фазы в шапке, кнопки ставок), снизу чат. Чат появляется только при работе через сервер: `node server.mjs`, затем `http://localhost:8080/race.html`. При открытии файла напрямую (file://) чата нет.

Кнопка «Hide chat / Chat» (справа сверху на телефоне, справа снизу на десктопе) прячет чат и отдаёт экран гонке; состояние хранится в localStorage, на скрытой кнопке показываются непрочитанные сообщения.

### Крипто-тематика гонки

- Имена по умолчанию: bitcoin, ethereum, solana, doge, xrp, cardano, tether, bnb, ton, pepe, shiba и мемные слова. У каждой монеты свой характер (bitcoin в очках, solana — дегенерат с ALL IN, tether — холдер и т. д.).

## Локации и персонажи (racevis.js)

Добавить локацию: запись в THEMES, добавить героя: запись в CHARS (racevis.js).
